# Windows Port Plan — Ultima V Native

Branch `windows/initial-port`, worktree `../ultima-v-native-windows`, based on
`main` at `96a55ff9` ("Refine T-Deck UI fidelity"). This document records the
architecture census done before the port, the decisions taken from it, what
was built, and what remains. It is updated as the work lands; the commit
hashes of each step are in [§9 Progress log](#9-progress-log).

---

## 1. Goal and constraints

A playable, independently buildable **Windows x64** build of Ultima V Native,
using **SDL3**, with:

- ONE gameplay implementation: the shared `native/core` and the T-Deck
  application layer are compiled unchanged; no gameplay is reimplemented;
- the T-Deck build and behaviour preserved (the host suite stays green; the
  firmware still compiles);
- an explicit **Original** mode (preservation, DOS keyboard, 1988 rules) and
  **Enhanced** mode (the project's existing optional enhancements);
- no copyrighted game data in the repository or the executable; assets come
  from the player's own installation;
- saves compatible with the T-Deck (and the DOS save bridge kept).

## 3. Architecture census (summary)

Nine read-only readers covered runtime, Board/display, input, storage,
resources/pack pipeline, audio, Original/Enhanced, ESP-IDF/compiler
portability and documentation. The findings that shaped the port:

**Application layer.** `tdeck::AlphaRuntime` (`native/targets/tdeck/main/alpha_runtime.{h,cpp}`)
is the whole application: it owns the game state, every core session, the
title/menus (`FrontendSession`), the System Menu, saves, audio policy and the
scene pacers, and is driven by `initialize()`, `handle(RawInputEvent)`,
`render(Board&)` and `loop_wait_ticks()`. Its direct ESP-IDF surface is small
(esp_timer, heap_caps, ESP_LOG, one FreeRTOS diagnostic). It already compiles
on a PC in ~60 host test targets, but those use a test fixture
(`attach_host_test_fixture`) — **the production `initialize()` had never run
off the device** before this port.

**Presentation.** `tdeck::Board` (`tdeck_board.cpp`, 1,813 lines) composes
every screen — title, menus, play frame, console, shops, endgame — and sends it
to the ST7789 panel as SPI windows of big-endian RGB565, redrawing only what
changed and relying on the panel to keep its contents. The host tests already
run it over a fake panel (`host_tests/board_shims/fake_tdeck_bus.cpp`), which
is a test model (timing model, unbounded instrumentation vectors) not fit to
ship.

**Input.** `RawInputEvent` is matrix-level (column/row, Sym/Alt/Shift) and
trackball pulses; `UiInputAdapter::translate` turns it into
`openu5::UiAction` / `DeviceShortcut`. Arrow keys cannot simply be fed as
trackball pulses (a speed-dependent accumulator with step gaps), and Escape
has no code (Cancel is the Mic key found by matrix position). After
translation, the runtime uses the raw event only for a log name, the
Movement-Mode source string and its timestamp.

**Storage.** All files are `"/sd/ultima5/..."` paths (ESP-IDF VFS) in
`alpha_save.cpp`, `alpha_resources.h`, `asset_pack.h`, `alpha_audio.h`,
`device_smoke_tests`; saves are two generations per slot plus a 32-byte commit
record; the device code already unlinks before rename (FATFS semantics). The
host tests redirect `/sd` with a force-included header (`sd_shims/host_sd_vfs.h`).

**Resources.** Two identity-locked packs (`openu5-assets.bin`,
`openu5-alpha1-resources.bin`: exact size + CRC checked in `main.cpp`) and an
optional audio pack. They are generated by TypeScript tooling
(`npm run extract`, a fixture generator, `pack:native`, `pack:alpha1`,
`pack:audio`); the resource pack embeds byte-exact `JSON.stringify` output, so
a C++ re-implementation of the generator would have to reproduce V8's JSON
formatting to pass the identity lock — not realistic for this port.
`native/core/src/loot.cpp` includes a git-ignored `loot_names.inc`, which is
regenerated byte-for-byte from the tracked `game/src/core/data/longEquipNames.json`.

**Audio.** The whole synth/pump/service stack is portable C++
(`openu5::AudioRingPump`, PC-speaker SFX synth, OPL2 music synth); only
`tdeck_audio.cpp` (I2S + FreeRTOS task) is device-specific. Music exists only
with the music-patched audio pack; nothing is synthesised for a stock game.

**Original / Enhanced.** There is **no mode flag** in the code. "Enhanced"
rules are the per-journey `EnhancedState` (Difficulty Original/Relaxed/Easy/Custom,
15 cheats, World toggles) stored in the save sidecar's `"enhanced"` key and
changed from the System Menu; Original = the defaults, guarded by preservation
golden tests. Several T-Deck input adaptations apply in every mode (spell
lists for Cast/Mix, list-only "Player:" prompts, Mic = Esc, WASD Movement
Mode, device key legends).

**Portability.** The core has no platform dependencies. GCC-only constructs:
five `__attribute__` sites (`perf_report.cpp` ×2, `input_controller.cpp`,
`alpha_runtime.cpp` ×2). C++20 is required (designated initialisers, `__VA_OPT__`).

## 4. Decisions

| # | Decision | Why |
|---|---|---|
| D1 | **MSVC (Visual Studio 2026, x64) is the primary toolchain**; CMake; C++20; static CRT (`/MT`) | requested; the core needed one two-line fix; a static CRT means no VC++ redistributable for players |
| D2 | **SDL3 3.4.16**, fetched by CMake `FetchContent` from the official release tarball, **pinned by SHA-256**; `UV_USE_SYSTEM_SDL3` / `FETCHCONTENT_SOURCE_DIR_SDL3` for installed or offline copies | reproducible, no package manager for builders or players |
| D3 | **Reuse `tdeck_board.cpp` unchanged over a production virtual ST7789** (`src/platform/virtual_panel.cpp`): the SPI/GPIO/LEDC calls the Board makes decode CASET/RASET/RAMWR into a persistent 320×240 RGB565 memory, which SDL presents scaled (nearest, integer by default) | pixel-identical to the device, zero firmware change, the same 320×240 logical screen |
| D4 | **ESP-IDF compatibility layer for Windows** (`native/targets/windows/esp_compat/` + `src/platform/`): real steady clock, rotating log file, malloc heap caps, sleeping `vTaskDelay`, real free-space query, the driver structs in ESP-IDF 6.1 field order | the shared sources compile unchanged; deliberately separate from the host-test shims, which carry virtual clocks and fault injection |
| D5 | **The `/sd` mount maps to a data directory** through a force-included redirect (`esp_compat/uv_storage_redirect.h`; wide-character Win32 calls, FATFS rename semantics, `_commit` for `fsync`, retries for antivirus locks). Layout = the SD card's: `<data>\ultima5\{packs, saves\, settings.json, import\, export\, logs\}` | the device code needs no path change; a T-Deck card's `ultima5` folder can be copied in and out |
| D6 | **Data directory**: `--data-dir`, else portable mode (`portable.txt` beside the exe → `<exe>\data`), else `%APPDATA%\Ultima V Native` | per-user, never the install folder; portable on request |
| D7 | **Desktop input**: `native/targets/windows/src/app/desktop_input.cpp` translates SDL keys to the existing `UiAction`/`DeviceShortcut` values; **one new public runtime entry, `AlphaRuntime::handle_action()`**, routes them through exactly the code path a translated T-Deck key takes (`handle_input_event` was split into translation + `route_input`) | no fake matrix events or trackball pulses; the T-Deck path is unchanged |
| D8 | **Interface mode** (Original/Enhanced) is a device-wide desktop setting (`ultima5\windows.json`), never part of the save. Original: DOS keyboard, no WASD mode, no quick-save keys, System Menu Difficulty/Cheats hidden. Enhanced: the existing enhancements. The journey's own rules always travel in its save; switching the interface never rewrites them | follows the census: rules are per journey, the mode is how the player drives the game |
| D9 | **Resource packs**: Windows enforces the T-Deck's identity gate (same size + CRC), and explains a missing or mismatched pack with a dialog that opens the data folder. Packs are made with the project's existing generator (documented, scripted) or copied from a prepared T-Deck card | byte-identical packs guarantee identical play; the generator cannot be reproduced in C++ for this port (§3) |
| D10 | **Audio**: `SdlAudioBackend` runs the unchanged `AudioRingPump` from SDL3's stream callback at the device's 16 kHz S16 mono; SDL resamples. Failure latches silent | identical sound to the device; no invented music |
| D11 | **Desktop settings** live in `ultima5\windows.json`; the game's `settings.json` is shared with the T-Deck unchanged | card interchange; `settings_document` drops unknown keys anyway |
| D12 | The shared application layer stays where it is (`native/targets/tdeck/main`); the Windows CMake lists the portable files and leaves out the device-only ones (`main.cpp`, `tdeck_input.cpp`, `tdeck_audio.cpp`, `sd_diagnostic_logger.cpp`, `system_perf.cpp`) | moving ~15 files would churn ~100 host-test paths and the firmware build for no behavioural gain; a physical move is a possible follow-up |
| D13 | **Platform profile in core** (`openu5/platform_profile.h`): the key names and storage words the menus and prompts print ("Mic returns" → "Esc returns", "Trackball: choose" → "Arrows: choose", "/ultima5/import" → "ultima5\import", the console banner), the Settings rows (the T-Deck's hardware rows vs the desktop's Interface/Display/Scaling rows), whether the System Menu lists Difficulty/Cheats, and two Original-mode behaviours (D14, D15). Every default is the T-Deck's literal, byte for byte | one shared UI, no copied strings; the pinned T-Deck strings and goldens keep passing (202/202) |
| D14 | **Desktop Original: Cast/Mix take the 1988 typed spell name** (CAST2.OVL:0x00DE, `re/notes/cast-input.md`): syllable initials A–Z except J/O, up to four, echoed as rune words, matched in any order against the 48 spells (`openu5/spell_entry.h`, initials derived from the core's own spell names); RETURN/Space end, ESC = "None!", no match = "No effect!". Enhanced keeps the list | "No enhanced quick-select menus" in Original; the T-Deck's list is its declared adaptation (A-17) and stays the default |
| D15 | **Desktop Original: Q is (Q)uit & Save** (CAST2.OVL:0x10FE): "Quit:", "Save game? " (DS 0x9658), N → "No", Y → "Yes" / "Saving..." / save to the journey's slot / "Done." (DS 0x966a, 0x96ac); play continues; no turn | the T-Deck replaces Q with its System Menu (declared adaptation A-5); on a full keyboard the original key is restored |
| D16 | **Digits pick the member in "Player:" prompts** on the desktop (both modes), as the 1988 roster prompt does; the Camp watch and Mix reagent pickers keep their own digit rules | done in the desktop key adapter (`SelectIndex`), no core change |

## 5. Layout

```
native/targets/windows/
  CMakeLists.txt           the target (core + platform + shared app + desktop + tests)
  cmake/LootNames.cmake    loot_names.inc from the tracked JSON
  esp_compat/              ESP-IDF API surface for Windows (headers)
    uv_storage_redirect.h  force-included into the shared device sources
    msvc/unistd.h          MSVC only
  src/platform/            esp_runtime, log, storage (/sd mount), virtual_panel,
                           sdlog_windows, device_glue
  src/app/                 application (boot + loop + autotest), desktop_input,
                           desktop_settings, data_paths, presenter, sdl_audio_backend
  src/main.cpp
  tests/                   Windows-target tests
```

Shared-code changes (all behaviour-preserving for the T-Deck):

- `native/targets/tdeck/main/alpha_runtime.{h,cpp}` — `handle_action()`,
  `input_mode()`, `accepts_direction_input()`; `handle_input_event()` split
  into translation + `route_input()`; the profile's banner and key words in the
  context bars and PC-transfer messages; the typed spell name and Q answers.
- `native/core/{include/openu5,src}/platform_profile.*` (new),
  `spell_entry.*` (new); `frontend.cpp`, `system_menu.{h,cpp}`,
  `ui_session.{h,cpp}` read the profile; `UiRequestId` gains `SpellName`,
  `MixSpellName`, `QuitSave` (appended, no value renumbers).
- `native/targets/tdeck/main/tdeck_board.cpp` — the Developer screen's two
  key legends through the profile.
- `__attribute__` portability guards (`#if defined(__GNUC__)`, the pattern
  `music_synth.cpp` already used) in `perf_report.cpp`, `input_controller.cpp`,
  `alpha_runtime.cpp`.

## 6. Phases

1. Worktree, baseline, census — done.
2. SDL3 bootstrap, compat layer, virtual panel, storage, runtime boot — done
   (the real `initialize()` runs; title, character creation and play verified
   by scripted runs).
3. Desktop keyboard (Original/Enhanced), window/fullscreen/scaling — first cut done.
4. Platform texts and settings rows (no "Mic"/"SD card"/"OpenU5" legends on
   Windows; desktop rows; Difficulty/Cheats gated by the interface mode).
5. Saves/settings tests, DOS save bridge on Windows, mode persistence.
6. Audio verification (device, offline render, synth goldens under MSVC).
7. Asset preparation path for players.
8. Tests, full host suite, T-Deck firmware compile.
9. Packaging (`UltimaV-Native-Windows-x64-dev.zip`) and documentation.

## 7. Known risks being tracked

- MSVC's libm may round the OPL synth's tables differently from GCC's
  (presentation only; checked against the host goldens in the Windows tests).
- The 32-byte save commit record must keep its layout under MSVC (static
  assertion in the Windows tests).
- Tracked core sources compile short verbatim game strings into every build
  (`shop_greetings.inc`, `shop_tables.inc`, `gem_category.inc`, and the
  equipment names) — this is pre-existing and also true of the published
  T-Deck firmware; flagged for the owner (§8), not changed by the port.

## 8. Open items for the owner

- Whether the tracked `.inc` files with short game strings are acceptable in
  a distributed Windows binary (as in the T-Deck binary today).
- A public version number for the first Windows release (this branch builds
  `0.5.0-dev`).
